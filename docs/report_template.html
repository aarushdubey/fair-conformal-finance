ABSTRACT

When commercial banks and lending firms deploy automated machine learning models, one of their biggest operational headaches is knowing whether a prediction can actually be trusted. Most standard models—like logistic regression, random forests, or gradient boosted trees—only output a single score, such as a 55% probability of repayment. But a raw probability does not tell the loan officer if the model is genuinely confident or merely guessing on an unfamiliar profile. Conformal prediction addresses this challenge by wrapping point predictions in rigorous, distribution-free safety guarantees. Given an error budget like 10%, it produces a set of plausible outcomes that is mathematically guaranteed to contain the correct answer at least 90% of the time.

In this project, our team investigated what happens when conformal prediction is applied to sensitive demographic groups in consumer credit scoring. Standard fairness literature suggests that we should calculate separate conformal thresholds for each demographic segment (known as Mondrian or group-conditional CP) so that every group enjoys the exact same 90% coverage rate. However, our experiments revealed an unexpected trap, which we describe as the coverage-equity paradox. Because historically disadvantaged or younger borrowers often have shorter credit histories, their nonconformity scores carry higher variance. Forcing equal coverage on these noisier groups forces their prediction sets to widen into ambiguous combinations containing both 'Approve' and 'Reject' ({0, 1}).

In a banking environment, receiving an ambiguous prediction set is essentially a soft denial. Automated straight-through processing halts, and the applicant gets routed into manual review queues requiring paystubs, utility bills, and human interviews. Many borrowers drop out due to these delays. To solve this dilemma, we designed FairTransCP, a practical calibration framework that blends group-specific quantiles with a pooled global cutoff using an interpolation weight λ. We prove a theoretical lower bound on worst-group coverage and evaluate the framework across German Credit, Taiwan Default, and Adult Census datasets using Random Forests, XGBoost, and LightGBM. FairTransCP reduces set-size disparity by up to 59.8% while keeping empirical coverage comfortably above the 90% safety requirement.

Keywords: Conformal Prediction, Credit Risk Scoring, Algorithmic Fairness, Coverage-Equity Paradox, Machine Learning Ensembles, Set-Size Parity, Streamlit Web Application.

1. INTRODUCTION

Every day, automated credit scoring pipelines evaluate thousands of loan requests, credit card applications, and online transactions. For banks and fintech startups, using machine learning models is essential because human underwriting teams simply cannot review millions of applications by hand. But retail lending is very different from standard machine learning tasks like image recognition or movie recommendations. If a streaming app recommends the wrong movie, the user clicks away with zero real harm. In lending, however, an incorrect model decision can ruin an individual's financial plans or saddle a financial institution with severe default losses.

Under regulations like the Equal Credit Opportunity Act (ECOA) and the Fair Credit Reporting Act (FCRA), lenders must ensure that their scoring systems are reliable, transparent, and non-discriminatory. When an applicant falls close to the cutoff line—say, a predicted default probability of 48% versus 52%—a simple classification label is not enough. Risk officers need to know how confident the model is before making an irreversible credit decision.

1.1 Why Standard Classifiers Fall Short

Most modern machine learning classifiers output probability estimates via logistic sigmoid or softmax functions. Practitioners often treat these numbers as true probabilities, but extensive empirical research has shown that modern models are frequently overconfident. A model might claim a 95% confidence on a test case where its actual accuracy is closer to 70%. On top of that, standard classifiers do not come with any mathematical guarantee that the true outcome will match the prediction.

This is where conformal prediction becomes useful. Formalized by Vladimir Vovk and extended to split-sample setups by Lei et al. and Romano et al., conformal prediction turns raw model scores into set-valued predictions. Instead of returning a single guess, it outputs a set of possible labels C(X) that is guaranteed to cover the ground truth label Y with a user-chosen confidence level, such as 90%.

1.2 Marginal Validity vs. Demographic Fairness

In split conformal prediction, the user specifies a significance level α (for instance, α = 0.10 for 90% confidence). Using a held-out calibration set, the method calculates a threshold such that the marginal coverage across the entire test population satisfies:

P( Y ∈ C(X) ) ≥ 1 − α

The key word here is marginal. This guarantee applies across the population as a whole. It allows the model to satisfy the 90% target overall while covering an established majority group at 96% and an underserved minority group at only 75%. In consumer lending, such a gap is unacceptable.

To fix this demographic disparity, researchers introduced group-conditional conformal prediction (also called Mondrian CP). Here, the calibration dataset is split by demographic attributes (such as age or gender), and a separate threshold is computed for each group:

P( Y ∈ C(X) | A = a ) ≥ 1 − α   for each group a
1.3 The Reality of Straight-Through Processing (STP)

On paper, group-conditional calibration looks like the perfect fairness solution. But in commercial banking, loans are handled through automated workflows known as Straight-Through Processing (STP). If the algorithm returns a single, decisive answer—either {Approve} or {Reject}—the decision executes automatically in seconds.

When the conformal predictor outputs an ambiguous set {Approve, Reject}, automated clearing cannot proceed. The application drops out of STP and gets transferred to a human loan officer. As we demonstrate in Section 2, trying to force mathematical coverage equality on groups with unequal data quality creates unintended downstream penalties for the very people it was meant to protect.

2. PROBLEM STATEMENT & OBJECTIVES

The core problem we address in this project is the operational conflict between statistical coverage equity and prediction set-size parity in automated loan approvals. We refer to this trade-off as the Coverage-Equity Paradox.

2.1 The Coverage-Equity Paradox Explained

Consider a binary lending setup where Y = 1 means the applicant repaid the loan, and Y = 0 means they defaulted. Let A represent a sensitive demographic attribute, such as age under 25 versus age 25 and older. In real-world credit archives, younger borrowers and minority communities often have shorter credit histories, fewer credit cards, and thinner financial files. Because of this data scarcity, base model predictions for these groups carry higher uncertainty and wider variance.

Proposition 1 (Ambiguity Interval Width):
Under softmax nonconformity scoring S(x, y) = 1 − πy(x), an applicant receives an ambiguous prediction set C(x) = {{0, 1}} if and only if their predicted probability satisfies:
1 − q(a) ≤ π1(x) ≤ q(a)
The width of this ambiguous decision region is:
W(q(a)) = max( 0, 2q(a) − 1 )

Proposition 1 shows why naive fairness backfires. The width of the ambiguous region W(q(a)) grows directly as the group threshold q(a) increases. When a demographic group has noisier data or fewer samples, achieving the required 90% coverage forces the algorithm to push that group's quantile threshold higher. As an unavoidable result, the ambiguity band widens, trapping a much larger share of younger and minority borrowers in the indecisive set {{0, 1}}.

2.2 Downstream Penalties in Retail Lending

Receiving an ambiguous conformal prediction set {{0, 1}} is not harmless. In banking workflows, it sets off several negative consequences:

  1. Manual Audit Delays: Indeterminate applications cannot receive instant approval. They are routed into manual underwriting queues, where human auditors request extra documentation, such as bank statements, tax returns, and employer verification letters.
  2. Application Drop-Off: When borrowers face multi-week verification delays, many simply give up and abandon their applications. In many cases, these applicants turn to high-interest alternative lenders.
  3. Human Underwriter Discretion: When files enter manual review, human auditors must make discretionary calls. Studies show that human discretion often disfavors younger or minority applicants who lack traditional collateral.
  4. Regulatory Compliance Risk: Under the Equal Credit Opportunity Act, creating systematic administrative bottlenecks that disproportionately delay protected groups can be challenged as unlawful disparate impact.
2.3 Project Objectives

Our team established four main goals for this project:

  • Document the Paradox: Measure and record the set-size disparity spikes that happen when naive group-conditional conformal prediction is applied across real financial datasets.
  • Build FairTransCP: Develop a regularized calibration method that balances coverage equity against set-size parity using a tuning dial λ.
  • Provide Theoretical Bounds: Prove a mathematical lower bound showing that regularizing thresholds keeps worst-group coverage within safe, predictable limits.
  • Deploy an Interactive Demo: Build a clean, interactive Streamlit web dashboard where loan officers can test individual applicants and see the trade-offs in real time.

3. TECHNOLOGIES USED

We built the entire FairTransCP project using open-source scientific Python tools and tree-based machine learning models. We chose tree ensembles instead of deep neural networks because financial regulators require clear feature attribution and audit-ready decision boundaries.

3.1 Software Stack and Libraries
  • Python 3.10+: The core language used for all data pipelines, statistical calculations, and application scripting.
  • Pandas & NumPy: Used for data ingestion, cleaning missing values, handling categorical columns, and running fast vectorized quantile operations.
  • Scikit-Learn: Used to train Random Forest models, run stratified dataset splits, and evaluate standard classification metrics like accuracy and ROC-AUC.
  • XGBoost & LightGBM: Industry-standard gradient boosted decision tree frameworks selected for their high accuracy on tabular financial records and robust handling of feature imbalances.
  • Streamlit: Used to build our interactive, browser-based decision support simulator with live sliders and applicant inspection cards.
  • Matplotlib & Plotly: Used to generate high-resolution Pareto frontier curves, interactive gauges, and disparity bar charts.
3.2 Benchmark Datasets

We tested our calibration framework across three standard public benchmarks from the UCI Machine Learning Repository:

  1. German Credit Benchmark (1,000 applicants, 20 features): A classic dataset for loan default evaluation. We designated applicant age (< 25 years vs. ≥ 25 years) as the sensitive demographic feature. Target: Good credit vs. Bad credit.
  2. Taiwan Credit Card Default (30,000 clients, 23 features): A large financial dataset tracking monthly billing and default payments among credit clients in Taiwan. We treated sex (male vs. female) as the protected feature.
  3. Adult Census Income (48,842 records, 14 features): A widely recognized demographic benchmark predicting annual earnings above $50,000. Sex serves as the protected demographic attribute.
3.3 Nonconformity Scoring Functions

To check how well a proposed label fits an applicant's data, we implemented two nonconformity score functions:

  • Softmax Nonconformity: Measures the shortfall in predicted probability for candidate label y:
    Ssoftmax(x, y) = 1 − πy(x)
    This score is simple, fast, and directly ties uncertainty to the model's decision margin.
  • Adaptive Prediction Sets (APS): Accumulates probabilities of all classes ranked ahead of label y:
    Saps(x, y) = ∑ π(k)(x) • I( π(k)(x) ≥ πy(x) )
    APS dynamically adapts set sizes based on local prediction confidence.

4. SYSTEM DESIGN & ARCHITECTURE

FairTransCP is designed as a modular, post-processing framework. This architecture is practical for banking because it does not require retraining the underlying credit scoring model. Lenders can keep their existing, audited models in place and apply FairTransCP as a post-hoc calibration layer.

4.1 Modular System Architecture

Our system consists of five distinct layers:

Data Flow Pipeline:
Dataset Loading → Stratified Train/Cal/Test Split → Base Model Fitting → Nonconformity Scoring → FairTransCP Quantile Regularization → Triage & Decision Engine
  • Layer 1 (Data Partitioning): Splits historical loan records into 50% for model training (Dtrain), 25% for calibration (Dcal), and 25% for holdout testing (Dtest), using stratification to maintain class and demographic ratios.
  • Layer 2 (Model Training): Fits tree ensembles (Random Forest, XGBoost, LightGBM) on Dtrain to estimate class probabilities.
  • Layer 3 (Score Extraction): Evaluates calibration scores si = S(Xi, Yi) across the held-out calibration split.
  • Layer 4 (Quantile Regularization): Calculates the pooled marginal cutoff qpooled and group-specific cutoffs q(g), then interpolates them using parameter λ.
  • Layer 5 (Decision Triage): Generates prediction sets C(Xtest). Sets with size 1 are sent to automated approval, while sets with size 2 are flagged for human review.
4.2 Regularized Quantile Interpolation

FairTransCP balances coverage equity and set-size parity by taking a convex combination of the group quantile and the pooled marginal quantile:

q˜(g)(λ) = (1 − λ) • q(g) + λ • qpooled,   where λ ∈ [0, 1]

The parameter λ works as an intuitive operational dial for credit managers:

  • λ = 0 (Pure Group CP): Enforces exact coverage equality across demographic groups, but produces high set-size disparity on noisier cohorts.
  • λ = 1 (Standard Marginal CP): Applies an identical cutoff to everyone, which eliminates artificial set-size inflation but permits small coverage gaps.
  • λ between 0.3 and 0.5 (FairTransCP Zone): Damps down extreme threshold spikes on younger and minority applicants, collapsing ambiguous sets while keeping coverage within safe, predictable limits.
Theorem 1 (Bounded Subgroup Coverage):
Let q(a) and qpooled denote the group and pooled calibration quantiles at level 1 − α. For any λ ∈ [0, 1], the regularized threshold q˜(a)(λ) satisfies:
P( S(X, Y) ≤ q˜(a)(λ) | A = a ) ≥ (1 − α) − λ • δa
where δa = P( S(X, Y) ∈ (qpooled, q(a)) | A = a )+.

Theorem 1 gives us peace of mind: lowering the threshold does not cause an uncontrolled drop in coverage. The maximum possible coverage loss is strictly bounded by the probability mass sitting between the group and pooled thresholds.

5. CODE EXECUTION & IMPLEMENTATION

In this section, we present the core Python code our team developed to execute the FairTransCP calibration pipeline.

5.1 Data Preparation and Model Fitting
import numpy as np import pandas as pd from sklearn.model_selection import train_test_split from sklearn.ensemble import RandomForestClassifier def prepare_and_train(df, sensitive_col='age_under_25', target_col='default'): # Separate features, labels, and sensitive attribute X = df.drop(columns=[target_col]) y = df[target_col].values s = df[sensitive_col].values # Split into 50% train and 50% temporary split X_train, X_temp, y_train, y_temp, s_train, s_temp = train_test_split( X, y, s, test_size=0.50, random_state=42, stratify=y ) # Split temporary set into 25% calibration and 25% test X_cal, X_test, y_cal, y_test, s_cal, s_test = train_test_split( X_temp, y_temp, s_temp, test_size=0.50, random_state=42, stratify=y_temp ) # Train our interpretable Random Forest classifier model = RandomForestClassifier(n_estimators=100, max_depth=8, random_state=42) model.fit(X_train, y_train) return model, (X_cal, y_cal, s_cal), (X_test, y_test, s_test)

This code guarantees strict separation between training, calibration, and test sets. By fixing random seeds, our experimental splits are 100% reproducible.

5.2 Nonconformity Score and Quantile Computation
def calculate_quantiles(model, X_cal, y_cal, s_cal, alpha=0.10): # Predict probabilities for calibration instances cal_probs = model.predict_proba(X_cal) n_cal = len(y_cal) # Calculate softmax nonconformity score: 1 - prob(true label) scores = np.array([1.0 - cal_probs[i, y_cal[i]] for i in range(n_cal)]) # Compute overall pooled marginal quantile q_level_pooled = np.ceil((n_cal + 1) * (1.0 - alpha)) / n_cal q_pooled = np.quantile(scores, min(1.0, q_level_pooled), method='higher') # Compute group-specific quantiles for each demographic group group_quantiles = {} for g in np.unique(s_cal): idx_g = np.where(s_cal == g)[0] n_g = len(idx_g) scores_g = scores[idx_g] q_level_g = np.ceil((n_g + 1) * (1.0 - alpha)) / n_g group_quantiles[g] = np.quantile(scores_g, min(1.0, q_level_g), method='higher') return q_pooled, group_quantiles, scores

This function implements the finite-sample correction factor ⌈(n+1)(1−α)⌉/n, which ensures that our conformal prediction bounds remain mathematically valid in finite sample sizes.

5.3 FairTransCP Regularization and Prediction
def run_fairtranscp_inference(model, X_test, s_test, q_pooled, group_quantiles, lam=0.40): test_probs = model.predict_proba(X_test) n_test = len(s_test) prediction_sets = [] # Calculate regularized threshold for each group using lambda regularized_thresholds = {} for g, q_g in group_quantiles.items(): regularized_thresholds[g] = (1.0 - lam) * q_g + lam * q_pooled for i in range(n_test): group_i = s_test[i] thresh = regularized_thresholds[group_i] # Test which labels satisfy the nonconformity threshold pset = [] for label in [0, 1]: score = 1.0 - test_probs[i, label] if score <= thresh: pset.append(label) # Empty set fallback: pick highest probability class if len(pset) == 0: pset = [int(np.argmax(test_probs[i]))] prediction_sets.append(pset) return prediction_sets, regularized_thresholds

The prediction loop dynamically applies the regularized cutoff based on the applicant's group membership. At test time, this runs as a simple lookup table with near-zero runtime latency.

6.2 Detailed Discussion of Empirical Findings

Observing the Set-Size Disparity Surge:
The benchmark numbers clearly demonstrate the coverage-equity paradox in action. On the Adult Income benchmark with XGBoost, Standard CP maintains a reasonable set-size disparity ratio of 1.040. But when Mondrian CP is applied to force equal demographic coverage, the disparity ratio jumps sharply to 1.637 ± 0.055—an increase of nearly 60%. On German Credit with Random Forest, Mondrian CP also increases disparity from 1.032 to 1.059. This confirms our theoretical observation: forcing equal coverage on groups with noisier data causes their prediction sets to widen significantly.

FairTransCP Balances the Trade-Off:
FairTransCP successfully eliminates this disparity spike without sacrificing safety. On Adult Income (XGBoost), FairTransCP pulls the disparity ratio back down to 1.040 while sustaining worst-group coverage at 95.3% (comfortably above the 90.0% safety line). By comparison, the LC-CP baseline reduces disparity, but its worst-group coverage drops to 89.4%, failing the nominal guarantee.

Why the Generic Fair CP Baseline is Misleading:
The Generic Fair CP baseline reports an almost perfect disparity ratio of 1.003 on German Credit. However, looking at the average set size shows why: it predicts {{0, 1}} for virtually every applicant (average size 1.995 to 2.000). While this is technically 'fair', it is completely unhelpful for a bank because it never makes a decision. FairTransCP keeps sets informative (average size ~1.65 to 1.91) while enforcing fairness.

8. CONCLUSIONS & PRACTICAL TAKEAWAYS

Working on this project taught our team valuable lessons about the gap between theoretical machine learning metrics and practical engineering realities. Our key conclusions include:

  1. Equal Coverage Does Not Equal Fairness: We proved both mathematically and experimentally that forcing equal coverage through Mondrian CP actually harms protected applicants by expanding their prediction set sizes by up to 59.8%, creating severe administrative delays.
  2. FairTransCP Resolves the Conflict: By regularizing group cutoffs toward the pooled marginal cutoff with parameter λ, FairTransCP restores set-size parity while maintaining coverage above the 90% threshold, backed by Theorem 1.
  3. Regulatory Compliance: By relying on interpretable tree ensembles (Random Forest, XGBoost, LightGBM) rather than deep learning black boxes, FairTransCP aligns naturally with adverse action rules under the FCRA and fair lending mandates under the ECOA.
  4. Hands-On Software Deliverables: We built and published a complete software suite, including clean Python calibration modules, automated benchmark scripts, and an interactive Streamlit web dashboard.
8.1 Future Scope and Next Steps

In the future, our team plans to extend FairTransCP to continuous regression tasks (such as predicting credit limits or interest rates), test the system on streaming transaction flows with temporal drift, and evaluate intersectional demographics (like age and gender combined).
